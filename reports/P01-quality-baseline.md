## 实际结果

30/30 输入完成真实检测和 OCR 诊断，随后执行安全覆盖流水线。诊断独立于擦字安全判断，避免只评估容易覆盖的区域。诊断韩文采用原裁图放大，与生产彩色笔画预处理不同，二者指标不可混算。

流水线检测到 101 处对白区域：7 处复用已有真实译文缓存并完成覆盖，94 处保留原文。保留原因如下：

| 原因 | 区域数 | 含义 |
|---|---:|---|
| 没有缓存且本轮禁用网络翻译 | 53 | 不是 API 故障，也不是翻译成功 |
| 气泡边界不闭合 | 32 | 当前安全策略拒绝擦字 |
| 文字超出安全区 | 3 | 原图保留 |
| OCR 置信度不足 | 5 | 不提交错误风险高的文字 |
| 深色或复杂气泡 | 1 | 尚无可接受修复策略 |

30 张安全区外改动均为 0 像素，只证明程序遵守其生成的掩膜。7 处缓存覆盖仍为未经人工确认的机器翻译。缓存运行前后字节一致，**新增翻译 API 请求为 0**，不能宣称完成了 30 张完整翻译实验。

原创夹具的自动真值评估：

| 夹具 | 匹配对白 / 真值 | 字符编辑错误 / 参考字符 | 端到端字符错误率 |
|---|---:|---:|---:|
| 普通韩文 | 1/1 | 0/18 | 0% |
| 低清小字号韩文 | 1/1 | 3/32 | 9.38% |
| 深底韩文 | 1/1 | 1/23 | 4.35% |
| 韩文接缝长图 | 2/2 | 1/43 | 2.33% |
| 日文竖排振假名 | 1/1 | 0/10 | 0% |
| 空白气泡 | 0/0 | 不适用 | null，误检 0 |

匹配要求覆盖至少 90% 真值文字区域且一对一；漏检按整段删除计入端到端错误。字符规范化为 NFKC、连续空白归一，保留单个空格；另存去空格口径。韩文夹具合计 5/116 字符错误（4.31%），样本极小且字形规则，不能外推到真实手写韩漫。日文指标评价正文，不证明擦除振假名无残留。

## 复现与核对

已有本机数据时启动只读对照页：

```powershell
.venv/Scripts/python.exe -m scripts.serve-quality
```

打开 `http://127.0.0.1:4177/`，每张显示原图、结果和未人工纠错的 OCR。只绑定回环地址、固定文件白名单，无翻译接口。主交互实验仍在 4176，二者用途不同。

重新跑基线须使用新 ID，防止覆盖证据：

```powershell
.venv/Scripts/python.exe -m scripts.run-quality-baseline --run-id baseline-v2
```

默认只读翻译缓存；有意发起真实免费请求才显式使用 `--allow-network`，仍受原持久预算限制。首次准备需要本地官方 PDF、字体、已登记模型与 Poppler；采集脚本拒绝覆盖冻结清单，联网下载必须显式指定 `--allow-download`。具体准备实现见 `scripts/prepare-quality-corpus.py`，不能将私有素材或权重推送仓库。
