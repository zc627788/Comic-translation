## 三种发布状态

| 状态 | 含义 | 必要条件 |
|---|---|---|
| DEVELOPMENT | 研发中 | 可以包含明确标记的 mock 和临时配置，不面向真实收费 |
| RELEASE_CANDIDATE | 候选版本可交付 | 全部 v1 必需功能与验证完成，授权/隐私核实，可构建安装 |
| PRODUCTION | 已在实际环境上线 | 部署/服务/真实收款配置和明确上线意图具备，生产 smoke 与回滚准备通过 |

当前状态以 [阶段状态](../../docs/progress.md) 为准。P01 已有基础工程，不代表具备翻译、模型基准或收费能力，也未达到 RELEASE_CANDIDATE 或 PRODUCTION。

## 仓库和版本策略

- 工作分支使用 `codex/` 前缀；本次文档基线分支为 `codex/spec-first-plan`。
- 不强推、不改仓库可见性、不随意覆写默认分支。远端出现新提交先读取并合并/变基处理，避免覆盖。
- 每次交付检查 UTF-8、无密钥、无私有样本/权重、依赖锁和实际版本一致。
- 提交使用能说明具体变化的消息。推送到已配置 origin 后核对远端分支 SHA 与本地 HEAD 相等。
- 版本标签在软件验证后创建；当前文档不创建暗示功能完成的 v1.0 标签。
- 文档报告说明对应代码/测试版本；最终总结提交本身无需自引用自己的 SHA，可引用前一构建提交并在对外交付给出最终远端 SHA。

## 部署和回滚顺序

1. 固定候选提交与构建产物校验和，备份数据库并记录 schema 版本。
2. 先应用向后兼容迁移；部署 API/worker，检查 readiness 和模型加载。
3. 在授权测试内容上跑 smoke：上传→识别→翻译→排版→覆盖→导出→删除；验证一次正常结算与失败释放。
4. 小范围放量观察失败、延迟、排队、成本和账本；再分发与该 API 兼容的插件包。
5. 异常先停止新增任务/付款入口并保留既有状态，回退应用版本；不要直接删除账本或强行回滚已产生交易的数据。
6. 服务回退需兼容已发布的扩展 API 版本。商店更新可能有延迟，服务器不能假定所有用户立即升级。

具体命令由 P06 根据实际环境补齐并演练。本文件不提供未经验证的一键生产部署命令。

## 运维指标与故障剧本

| 观察项 | 初始告警/处理原则 |
|---|---|
| API/worker 不可用 | readiness 失败停止接新任务，保留查询/恢复通道 |
| 长时间排队 | 限制新批次并说明等待，不无限收取预留 |
| 模型/供应商错误 | 有界重试和熔断，切换必须符合披露与预算 |
| 单用户成本异常 | 限流与预算上限，检查重试/缓存/滥用，不默认人工看内容 |
| 账本不一致 | 停止受影响扣费，按任务和支付事件对账；修正以补偿流水 |
| 对象存储增长 | 按保留策略清除，核对删除队列和备份轮替 |
| 图片质量退化 | 对固定集复测，回退模型/参数版本，分层查看而非只看总平均 |
| 站点改版 | 标记受影响适配，保留单图/手动入口，避免误盖其他图 |

告警阈值在实际容量和试用负载中校准。默认不因一次用户取消就报警；关键账务、安全问题不等待大量样本。
