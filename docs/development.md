# 本地启动与第一步验证

当前阶段：P01 基础工程。已有可构建的插件开发面板、可启动的本地 API、worker 诊断入口和自有阅读器。尚未接入 OCR、检测、擦字、翻译和数据库任务队列。

## 环境

Windows / PowerShell，Node >=22.12，Python 3.12。本机实际验证 Node 25.9.0 / npm 11.12.1 / Python 3.12.10；CI 配置使用 Node 24 / Python 3.12。云端 CI 是否通过需看对应提交结果，本机检查不能代替。

Python 运行库安装到 `.venv`，uv 工具安装到 `.local/tools`；不会改系统默认 Python。基础工程不需要 Docker、GPU 或翻译 API。之后数据库/队列与模型实验另行接入。

## 首次准备

在项目根目录的 PowerShell 中执行：

```powershell
.\scripts\setup.ps1
.\scripts\check.ps1
```

setup 根据 `package-lock.json` 和 `uv.lock` 安装依赖，可能需要网络；不下载漫画模型，也不调用付费服务。文本和输出使用 UTF-8。网络中断或校验失败时停止安装，重新运行；不得关闭完整性校验。

check 验证文档、类型、扩展包、阅读器服务器边界、后端 API 和真实本地服务启动。它会在临时端口启动并停止自己的后端进程，不修改已有服务。

## 打开测试阅读器

在一个终端运行：

```powershell
npm run fixtures
```

打开 [自有测试阅读器](http://127.0.0.1:4173)。端口 4174 提供跨域测试图。按 Ctrl+C 停止。

页面包括正常图、响应式图、重复图、图标、广告布局、跨域图、换源、故意失败、懒加载长图和动态追加。SVG 是自有网页夹具，不是模型质量评估样本。

## 启动本地 API

另开一个终端运行：

```powershell
.\scripts\start-api.ps1
```

本地 API 只监听 127.0.0.1:8765。`/health/live` 应返回 200；`/health/ready` 应返回 503，因为模型没有接入。`POST /v1/batches` 必须返回 MODEL_NOT_READY，不创建任务，不扣费。服务存活与翻译就绪是两种状态。

查看当前 worker 能力：

```powershell
.\.venv\Scripts\python.exe -m services.worker
```

仅输出各模型能力不可用；加 `--check-ready` 会以非零退出，供后续部署探针检查。

## 加载开发插件

```powershell
npm run build
```

1. 在 Chrome 或 Edge 的扩展管理页打开开发者模式。
2. 选择“加载已解压的扩展程序”，选择项目下 `dist/extension` 文件夹。
3. 打开自有阅读器，在工具栏点击本插件图标。
4. 侧栏点击“扫描当前页图片”，只列图片尺寸/加载状态。
5. 启动 API 后点击“检查服务连接”；正常情况下提示本地服务已启动、翻译模型未接入。

当前包仅为本地开发版，包含本机服务访问权限。扫描是用户主动动作，不持续扫描其他标签页，不读取像素/上传图片；不包含缩略图智能推荐、原位翻译或导出。这些按后续阶段实现。

插件实际安装和跨浏览器授权行为仍需真实验收，打包检查不证明它们已通过。当前构建没有配置商店发布，也没有替用户更改浏览器设置。

## 本轮验证范围

- Windows 项目隔离依赖安装及锁文件。
- TypeScript 检查、Vite 扩展构建、manifest/入口/脚本资源检查。
- API 基础测试与真实启动；模型能力明确不可用。
- 固定路径阅读器服务器；仓库文件、配置与任意路径不可通过服务读取。
- 浏览器中验证自有阅读器图片显示、跨域来源、换源、懒加载、追加。

不包括：实际插件运行验收、真实漫画、检测/OCR/修复/翻译质量、GPU 速度、计费、生产部署。
