# 研发路线与逐步交接

版本：0.1；日期：2026-09-28；范围：从需求到可收费版本的实施路线。

## 输入与上一份总结

这是文档链起点。输入为用户提出的网页扫描、缩略图智能选择、原位翻译、导出、Ctrl+Shift+左键翻译，以及逐 Markdown 交接并推送仓库的要求。前期调研确认存在竞品，但质量、成本、许可证和商业需求尚未实测。

本轮先完成完整开发规格并提交 Git；后续按以下阶段逐个实现。不能将“规划了商业化”表述为“已经可以收费”。

## 八个研发阶段

| 阶段 | 目标 | 必须交付 | 完成判据 | 依赖 |
|---|---|---|---|---|
| P00 | 需求与可执行规格 | 全套 Markdown、追踪表、交接模板 | 文档一致性检查通过，开放决策明确 | 用户需求 |
| P01 | 技术验证与基础工程 | 可启动工程、模型实验、站点样本、授权记录、成本基线 | 真实链路验证可用；未决授权有明确影响范围 | P00 |
| P02 | 单图完整链路 | 真实 OCR、翻译、擦字、排版、网页覆盖、原图恢复 | 授权样本上能真实完成并处理失败 | P01 |
| P03 | 完整阅读交互 | 批量扫描、筛选、快捷键、任务队列、导出、纠错 | 三种入口共享结果；刷新、缩放和失败场景通过 | P02 |
| P04 | 漫画质量与效率 | 振假名、上下文、长图、复杂背景降级、成本优化 | 固定测试集达标并有盲评记录 | P03 |
| P05 | 账户和商业化 | 登录、额度账本、套餐、支付沙箱、数据删除 | 不重复扣费、不越权、退款与订阅状态一致 | P04 |
| P06 | 发布前验证 | 安全、兼容、性能、隐私、安装包、运维和回滚演练 | 发布清单通过，关键缺陷为零 | P05 |
| P07 | 交付与发布准备 | 用户指南、版本包、完整总结、Git 远端验证 | 代码与证据已推送，可复现构建；上线状态如实记录 | P06 |

P07 中“代码交付完成”与“生产上线完成”分开。真实上线需要具备服务商账户、商用授权、结算配置及用户明确部署意图；缺失时只能交付候选版本，不能宣称商业上线。

## 阶段执行协议

1. 读上一阶段报告全文，核对版本、输入产物、未决事项和证据，不只读一句 PASS。
2. 在本阶段报告记录“上一阶段完整总结”：目标、成果、验证、未完成事项、影响和接收判断，并链接上一份报告。
3. 按任务实施，记录实际命令、环境、耗时、样本、失败结果和修复。不把拟执行命令写成已执行。
4. 完成后写本阶段完整总结：交付文件、需求覆盖、测试结果、缺陷、授权/成本变化、下一阶段输入。
5. 根据门槛写明“可以执行下一步：Pxx，理由……”或“不可以执行下一步，阻塞项……”。在开始下一阶段之前告知用户该结论。
6. 更新进度、任务勾选、规格变更和 Git 交付记录。进入下一阶段时先消费这份总结。

## 状态和放行

- NOT_STARTED：尚未执行。文档有计划也不能改为完成。
- IN_PROGRESS：已开始，但未满足全部验收。
- BLOCKED：存在具体依赖阻塞；可继续不依赖该阻塞的工作，但不能跳过相关门槛。
- COMPLETE：验收完成并有证据，下一阶段可开始。
- REOPENED：后续变化使之前验收失效，需明确重新验证范围。

放行结论只有 PASS 或 HOLD。没有“默认通过”。低优先级遗留事项可以延期，但必须有任务编号、理由、修复阶段，而且不影响当前阶段完成判据。安全、计费一致性、真实链路和商用授权问题不能用备注掩盖。

## 范围和交付纪律

规格基线为桌面 Chrome/Edge、日译简中、普通图片阅读页面。后续新增语言、手机端、全站适配或专业出版编辑器走变更记录。

用工作分支正常提交和推送，禁止强制覆盖远端。推送后核对远端提交哈希；没有远端证据不能说“已 push”。
